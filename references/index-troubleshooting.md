# 收录异常排查决策树

**核心原则：先判状态，再动手。**四个状态病因完全不同，混用会白改好几轮，每次改动都要 3~7 天才能看到结果。

状态从 GSC 的 **Indexing → Pages** 看（新版界面术语：不是 "Search Results"，是 **Performance**；索引报告在 **Indexing → Pages**）。

---

## 分支 0：先排除整站级故障（5 分钟内可查完）

站点整体掉曝光 / 掉收录时，按这个顺序查，**不要先怀疑算法**：

1. `curl -sI <base>` 是否 200、证书是否正常。
2. `python3 scripts/seo_check.py robots <base>` —— 有没有 `Disallow: /`。有站就是 robots 误挡导致 AdSense 判"网站已下线"。
3. 全站是否被加了 `noindex`（部署配置写错、模板环境变量没注入，会一次性全站加）。
4. 服务器是否在海外、Googlebot 是否可达（D-1）。从机房视角 `curl -A "Googlebot"` 模拟一次。
5. GSC 有没有 Manual actions（手动操作）。
6. **preview / staging 域名是否被收录**（D-4）——重复内容会让主站权重分裂。
7. 以上都正常，再看时间点是否对上已知算法更新时间。

做完这 7 条再往下走，否则会在错误分支上耗几天。

---

## 分支 1：未发现（URL 不在 GSC 任何报告里 / sitemap 里没有）

**判断**：URL Inspection 显示 "URL is unknown to Google"。

**病因**：没有任何路径让 Google 知道它的存在。

**动作**：
1. 确认它在 sitemap 里（U-10：自动生成，不是手写）。
2. **加内链**：首页或最热栏目页 1 条 + 2 个内容相关页各 1 条（I-5）。这是比 sitemap 快得多的发现路径。
3. 再 `Request Indexing`（每天约 10 条配额，按 8 条一批排）。
4. 确认没有 `noindex`、没被 robots 挡。

**不该做**：反复改 sitemap 文件、反复提交同一个 URL。

---

## 分支 2：已发现 - 当前未编入索引（Discovered - currently not indexed）

**判断**：GSC 里这个状态。

**病因**：Google 知道有这个 URL，但还没排上抓取。**新站这是完全正常的排队状态**，不是故障。

**动作**：
1. 什么都不改，等 1~3 周。
2. 想加速就加内链提权（I-5），把首页和其它页的链接指过去。
3. 检查全站是否有大量低质页在消耗抓取预算（P-3 / P-7），有就先停放量。

**不该做**：改文件、刷 `lastmod`、反复点 Request Indexing。这三件事都不影响排队顺序，只会浪费配额并让判定基准漂移。

---

## 分支 3：已抓取 - 当前未编入索引（Crawled - currently not indexed）

**判断**：GSC 里这个状态。**这是质量问题：Google 抓了但认为不值得收。**

**病因（按出现频率）**：
1. 与站内另一个页面撞题（自相残杀）。
2. "一个事实撑一页"——只有发售日 / 一个参数，增量内容被首页或聚合页覆盖。
3. 在转述竞品第一名的内容，没有自己的增量。
4. 模板化页面去掉变量后与兄弟页高度重复（P-7）。

**动作 —— 重定位（换角度），不是堆字数**：
1. 先三查病因：跟哪个内页撞题 / 是否只有一个事实 / 是否在转述竞品。
2. 换角度重写：撞题的那段**删掉，改成一两句 + 链接指向主题专页**。
3. 一个页面只放一份核心资产：一个放表格（速查），一个放正文（原理），不要两页同放同一份规则表。
4. 改完提交一次索引（不在验证队列的页才提交）。

⚠️ **堆字数对这个状态无效。**加厚只对"还没被抓过、曝光≈0"的页有效；已经判了"抓了不收"，病因是重复，加长只会更重复。

---

## 分支 4：已收录，但没有排名 / 排名很低

**判断**：GSC 显示已编入索引，Performance 里有曝光但位置 > 20，或曝光≈0。

**病因**：
1. **关键词打不过**：SERP 前 10 全是 Wikipedia / Reddit / 大媒体。
2. **意图错配**：用户搜的是"怎么用"，你做的是"是什么"。
3. **权重不够**：位置 7~15 且曝光高、点击低，是权重问题不是内容问题。
4. **词被别页抢走**：目标词其实由首页或另一个内页承接了（这在判断"要不要新建页"时最容易搞错）。

**动作**：
1. 先 `grep` 全站 title / description / h1，确认这个词现在到底由哪个页面承接。**"无专页"必须验证，不能凭印象。**
2. 权重不够 → 只改内链锚文本（I-6），不动正在排名的正文，风险接近 0。
3. 意图错配 → 改 title / h1 / 首段的角度。
4. 打不过 → 换更长尾的词，或接受现状转做其它簇。
5. **合格候选可以是 0，那就一页都不上。**不要为了维持节奏造页。

---

## 分支 5：收录数正常但流量不涨

1. 曝光涨、点击不涨 → CTR 问题：改 title / description，看 SERP 里竞争对手的表述。
2. 曝光不涨 → 词太小或排名太靠后，回到分支 4。
3. 有排名、有点击、无转化 → 不是 SEO 问题，是落地页承接问题（I-8：锚文本承诺必须兑现）。
4. 品牌词占比过高 → 非品牌流量没起来，看内容覆盖是否只覆盖了品牌词。

---

## 排查记录模板

每次排查写进项目 memory，四行就够：

1. 站点 / 日期 / 触发原因（谁的判断或哪条数据）
2. 状态判定（哪个分支）+ 依据的 GSC 截图或数字
3. 采取的动作 + 预期生效窗口（发现 1~3 周 / 重爬 3~7 天 / 内容重定位 2~4 周）
4. **基线数字**：改之前先存 GSC 的曝光 / 点击 / 平均位置截图，否则改完无法回答"涨了还是掉了"

⚠️ 改已排名的页面（尤其首页）之前**必须存基线**，这是唯一能做事后归因的办法。
